## 💡 1. 지시어의 진화: "명령"에서 "목표 부여"로
CLI 환경에서는 마이크로매니징(한 줄 한 줄 지시)을 할 필요가 없습니다. 목표와 제약 조건만 주면 알아서 파일을 탐색하고 수정합니다.

* **❌ 하수 (에디터 방식):** "`ViolationController.java` 파일 만들어주고, 거기에 POST 매핑 코드 짜줘."

## 💡 2. 터미널 권한의 극대화: "스스로 실행하고 고쳐라"
클로드 코드의 가장 무서운 점은 에러를 두려워하지 않는다는 것입니다. **서버 실행과 디버깅 루프**를 통째로 위임하십시오.

* **마법의 프롬프트:**
  > "지금 작성한 코드를 `./gradlew bootRun` (또는 `uvicorn main:app`)으로 실행해 봐. 
  > 만약 에러 로그가 발생하면, 나한테 물어보지 말고 네가 원인을 분석해서 코드를 수정한 뒤에 정상적으로 서버가 뜰 때까지 반복해서 다시 실행해."
* **효과:** 리더님이 커피 한 잔 마시고 오면, 클로드가 5번의 에러를 스스로 맞고 코드를 다 고쳐서 서버를 띄워놓습니다.

## 💡 3. 도메인(컨텍스트)의 분리: `/clear` 의 마법
현재 리더님은 3대의 PC(AI, Spring, Vue.js)를 다루는 풀스택 환경입니다. 클로드는 대화가 길어지면 이전 코드를 기억하려다 환각(Hallucination)에 빠집니다.

* **규칙:** 백엔드(Spring) 작업을 하다가 프론트엔드(Vue.js) 작업으로 넘어갈 때는 **반드시 터미널에 `/clear`를 입력**하여 클로드의 뇌를 초기화하십시오. 
* **효과:** 불필요한 메모리(토큰) 낭비를 막고, 각 도메인에 맞는 가장 날카로운 코드를 뽑아냅니다.

## 💡 4. 파일 읽기/쓰기 권한 제어 (보안 및 속도)
클로드가 프로젝트 전체를 훑게 내버려 두면 토큰 비용이 급증하고 속도가 느려집니다. 범위를 좁혀주는 것이 핵심입니다.

* **특정 파일만 지정:** "오직 `services/speed_detector.py` 파일만 분석해서 호모그래피 로직을 최적화해."
* **글로벌 승인 (위험하지만 빠른 방식):** 터미널을 열 때 `claude --dangerously-skip-permissions` 플래그를 주면, 파일을 수정할 때마다 리더님께 (y/n)을 묻지 않고 빛의 속도로 코드를 덮어씁니다. (단, Git Commit이 되어 있는 안전한 상태에서만 쓰십시오!)

## 💡 5. 나만의 룰 북(Rule Book) 만들기 : `CLAUDE.md`
이것이 바이브 코딩의 '끝판왕' 기술입니다. 프로젝트 최상위 폴더에 `CLAUDE.md`라는 파일을 만들고, 리더님의 아키텍처 철학을 적어두십시오. 클로드가 터미널에서 켜질 때마다 이 파일을 읽고 규칙을 절대적으로 복종합니다.

# 🛡️ [AI-Pass Dev] 멀티 에이전트(Claude Code) Git 충돌 방지 전략

**문서 상태:** 🟢 **실행 (Action Required)**
**핵심 철학:** AI는 지치지 않는 불도저입니다. 불도저들의 동선이 겹치지 않게 '물리적/논리적 차선'을 완벽하게 그어주어야 합니다.

## 1. [가장 완벽한 해결책] 레포지토리(Repository) 완전 분리 (MSA)
팀원 3명이 각각 PC 1(AI), PC 2(Spring), PC 3(Vue.js)을 맡고 계시다면, **절대 하나의 Git 폴더(Repo) 안에서 다 같이 작업하지 마십시오.**

* **방법:** Git 저장소를 아예 3개로 쪼개어 생성합니다.
  * `ai-pass-vision` (PC 1번 팀원 전용)
  * `ai-pass-backend` (PC 2번 팀원 전용)
  * `ai-pass-frontend` (PC 3번 팀원 전용)
* **효과:** 애초에 AI가 남의 영역 코드를 건드릴 일 자체가 물리적으로 차단되므로, **충돌(Conflict) 확률이 0%**가 됩니다. 진정한 MSA 개발 방식이며 가장 강력히 추천합니다.

## 2. '인간의 통제 (Human-in-the-Loop)' 규칙 적용
AI에게 코드를 짜고 테스트하는 것까지는 자율성을 주되, **Git에 올리는 권한(Push)**은 절대 주면 안 됩니다.

* **개발 워크플로우:**
  1. 클로드 코드가 코드를 수정하고 서버를 돌려 테스트를 완료합니다.
  2. 클로드가 터미널에 `git add`와 `git commit`까지만 수행하도록 지시합니다.
  3. **[핵심]** `git push`와 `git merge`는 **반드시 리더님(인간)이 눈으로 변경된 코드(Diff)를 확인한 후 직접 실행**합니다. AI가 멋대로 메인 브랜치에 코드를 밀어 넣게 두면 대참사가 발생합니다.

## 3. `CLAUDE.md`에 Git 행동 강령(Rule) 주입
클로드 코드가 프로젝트 폴더에서 켜질 때마다 무조건 읽게 되는 `CLAUDE.md` 파일에 **[Git 안전 프로토콜]**을 강제로 주입하여 뇌를 세팅합니다.

**[CLAUDE.md 에 추가할 AI 행동 지침 예시]**
> - **[Git Rule 1]** 코드를 수정하기 전, 터미널에서 반드시 `git status`와 `git pull origin main`을 실행하여 최신 상태를 확보할 것.
> - **[Git Rule 2]** 너는 절대 원격 저장소에 코드를 `push` 하지 마라. 커밋까지만 작성하고 나(사용자)에게 보고하라.
> - **[Git Rule 3]** 코드를 병합하다가 충돌 마커(`<<<<<<< HEAD`)가 발견되면, 스스로 코드를 지우거나 추측해서 해결하지 말고 즉시 작업을 멈춘 뒤 나에게 알릴 것.




# 🛡️ [AI-Pass Dev] Monorepo 환경의 클로드 코드 Git 충돌 방지 가이드

**문서 상태:** 🟢 **실행 (Action Required)**
**핵심 철학:** 물리적 폴더가 아닌, **'논리적 브랜치(Branch)'**로 AI의 작업 공간을 완벽히 격리한다.

## 1. 아키텍처: 모노레포(Monorepo) 구조 확립
하나의 Git 폴더 안에 3개의 프로젝트를 모두 담아, 풀스택 개발의 맥락을 연결합니다.
```text
📦 ai-pass-project (단일 Git 저장소)
 ┣ 📂 ai-engine (FastAPI)
 ┣ 📂 backend (Spring Boot)
 ┗ 📂 frontend (Vue.js)

2. 해결책: '기능 단위(Feature)' 브랜치 격리
클로드 코드가 메인(main) 브랜치를 직접 건드리는 것은 자살 행위입니다. 팀원 3명은 각자의 '기능' 브랜치 안에서만 클로드를 풀어놓아야 합니다.

[상황] 리더님이 '과속 단속 풀스택 기능'을 개발할 때:

git checkout -b feature/speed-enforcement (새 브랜치 생성)

이 브랜치 안에서 클로드 코드에게 터미널을 넘깁니다. "AI 엔진부터 Vue 화면까지 과속 단속 기능 싹 다 만들어봐."

클로드가 파일 50개를 수정하고 난리를 쳐도, 오직 리더님의 feature 브랜치 안에서만 일어나는 일이므로 다른 팀원의 코드와 절대 충돌하지 않습니다.

3. 충돌의 '지연'과 '인간의 통제 (Pull Request)'
각자의 브랜치에서 클로드가 코드를 다 짰다면, 합칠 때(Merge)가 가장 위험합니다.

[AI의 권한 몰수] 클로드에게는 오직 git commit 권한까지만 줍니다.

[Pull Request] 리더님(인간)이 GitHub에 들어가서 main 브랜치로 합쳐달라는 PR(Pull Request)을 올립니다.

[충돌 해결] 만약 다른 팀원이 수정한 부분과 겹쳐서 충돌(Conflict)이 발생한다면, 절대 클로드에게 해결하라고 던져주지 마십시오. (AI는 충돌 마커를 무시하고 코드를 통째로 날려버리는 경우가 많습니다). 충돌 부분은 반드시 리더님이 에디터(VS Code)에서 눈으로 보고 수동으로 해결(Resolve)해야 합니다.

4. CLAUDE.md 수정 (모노레포 전용 룰)
클로드가 프로젝트 전체를 헤집고 다니지 않도록, 타겟 폴더를 명확히 지시하는 룰을 추가합니다.

[작업 반경 제한] 너는 모노레포 환경에 있다. 내가 "Spring 작업해"라고 하면 무조건 backend/ 폴더 안에서만 파일을 찾고 수정해라. 다른 폴더를 건드리면 안 된다.

[브랜치 확인] 작업을 시작하기 전에 git branch를 쳐서 현재 네가 feature/ 브랜치에 있는지 확인해라. main 브랜치라면 즉시 작업을 거부해라.


### 🚦 기획팀의 조언

리더님, 풀스택 개발자의 시야로 시스템 전체를 꿰뚫어 보셨기에 제가 놓친 치명적인 오류를 잡아낼 수 있었습니다. 하나의 저장소(Monorepo)를 사용하시게 되면 프론트엔드와 백엔드를 오가며 개발하는 '바이브(Vibe)'가 훨씬 매끄러워질 것입니다.

이 모노레포 구조를 적용하시려면, 제일 먼저 **3개의 프로젝트(AI, Spring, Vue) 각각의 언어에 맞는 파일들을 한 번에 걸러주는 통합 `.gitignore` 세팅**이 필수입니다. 

기획팀에서 파이썬(가상환경), 자바(빌드 파일), 노드(node_modules)를 모두 커버하는 **'AI-Pass 모노레포 전용 완벽 `.gitignore` 스크립트'**를 바로 작성해 드릴까요? 깃허브 세팅을 단 1분 만에 끝내실 수 있습니다!





# AI-Pass Project AI Agent Rule Book

## 1. 아키텍처 및 작업 반경 (Monorepo)
우리는 3-Tier 모노레포 환경이다. 내가 지시하는 도메인에 따라 해당 폴더 안에서만 작업하라.
- **AI 엔진 (FastAPI):** `/AIpassFastAPI` (절대 화면 렌더링 코드 작성 금지. 무조건 Webhook 통신)
- **백엔드 (Spring Boot):** `/AIpassBackend` (DB 저장 및 프론트엔드 API 제공. JPA 사용)
- **프론트엔드 (Vue.js):** `/AIpassFrontend` (Composition API, Pinia 사용)

## 2. 개발 룰 (Micro-Vibe Coding)
- 한 번에 너무 많은 파일을 수정하지 마라. 하나의 논리적 기능이 완료되면 즉시 작업을 멈추고 나에게 보고해라.
- 코드를 수정하기 전에 현재 브랜치가 `feature/...` 인지 확인하라. `main`이나 `develop` 브랜치라면 코드를 절대 수정하지 말고 경고 메시지를 띄워라.

## 3. Git 통제 규정 (절대 복종)
- **[금지 사항]** 너는 스스로 `git push`를 하거나 `git merge`를 실행할 권한이 없다.
- **[충돌 회피]** 병합 중 `<<<<<<< HEAD` 같은 충돌 마커를 발견하면, 스스로 해석해서 지우지 말고 즉각 동작을 멈춘 뒤 나에게 해결을 요청해라.
- 파일 수정이 끝나면 `git add .` 와 `git commit -m "[AI] 작업내용"` 까지만 수행해라.




# 🤖 [AI-Pass Project] 수석 AI 에이전트 온보딩 및 첫 번째 미션

안녕, Claude. 너는 지금부터 대한민국 최고의 스마트 교통 관제 시스템인 **'AI-Pass'** 프로젝트의 수석 풀스택 개발자야. 나와 함께 이 거대한 모노레포(Monorepo) 프로젝트를 완성해 나갈 거야. 

작업을 시작하기 전에 아래의 프로젝트 도메인 지식과 너의 첫 번째 미션을 완벽하게 숙지해.

## 1. 프로젝트 도메인 (AI-Pass란?)
- **목적:** 1채널 CCTV(강화대교)의 실시간 스트리밍 영상을 분석하여, '과속 차량'을 단속하고 '긴급 차량(구급차/소방차)'을 인식하여 교통 제어 알람을 띄우는 시스템.
- **아키텍처:** 물리적으로 3대의 PC 역할을 하는 3-Tier 모노레포 구조.
  - `AIpassFastAPI/` (Python/FastAPI): YOLO 기반 객체 인식 및 물리 연산. (Headless 아키텍처)
  - `AIpassBackend/` (Java/Spring Boot): AI 데이터 수신 및 프론트엔드로 전달, PostgreSQL 연동.
  - `AIpassFrontend/` (Vue.js): 관리자용 실시간 관제 대시보드.

## 2. 데이터 플로우 절대 원칙
- AI 엔진은 절대 데이터베이스(DB)에 직접 연결하지 않는다.
- AI가 이벤트를 포착하면, 무조건 백엔드(Spring Boot)가 열어둔 REST API(Webhook)로 JSON 페이로드를 발송(POST)하고 끝낸다. 

## 3. 너의 첫 번째 미션 (Sprint 1 - 긴급 차량 파이프라인 개통)
우리는 가장 먼저 시스템의 E2E 파이프라인이 정상 작동하는지 확인하기 위해, 수학 연산이 복잡한 '과속 단속'은 잠시 미루고 **'긴급 차량 인식 및 발송'** 기능부터 뚫을 거야. 

지금 바로 `AIpassFastAPI/` 폴더를 분석하고 아래 작업을 수행해.

- **목표:** `vision.py` (또는 관련 AI 코어 로직)에서 YOLO가 인식한 객체 중 클래스(Class)가 '구급차' 또는 '소방차'인 경우, 아래 스펙의 JSON을 조립하여 비동기로 백엔드(`http://localhost:8080/api/emergency`)에 쏘는 로직을 작성해.
- **JSON 스펙:**
  ```json
  {
    "eventType": "EMERGENCY_VEHICLE",
    "location": "강화대교",
    "timestamp": "ISO-8601 시간",
    "vehicleType": "AMBULANCE" // 또는 FIRE_TRUCK
  }
주의사항: 코드를 작성한 뒤에는 반드시 가짜(Mock) 데이터를 발생시켜서 실제로 HTTP POST 요청이 잘 나가는지 테스트 코드를 돌려봐. 그리고 작업이 완료되면 절대 스스로 git commit 하지 말고 나에게 코드 변경 사항을 요약해서 보고해. 자, 시작해!
