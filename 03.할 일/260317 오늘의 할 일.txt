# 🚀 [AI-Pass Dev] Claude Code CLI 100% 활용 마스터 가이드

**문서 상태:** 🟢 **실행 (Action Required)**
**핵심 철학:** AI에게 '코딩'을 시키지 말고, '문제 해결'을 지시하라.

## 💡 1. 지시어의 진화: "명령"에서 "목표 부여"로
CLI 환경에서는 마이크로매니징(한 줄 한 줄 지시)을 할 필요가 없습니다. 목표와 제약 조건만 주면 알아서 파일을 탐색하고 수정합니다.

* **❌ 하수 (에디터 방식):** "`ViolationController.java` 파일 만들어주고, 거기에 POST 매핑 코드 짜줘."
* **🟢 고수 (CLI 방식):** "현재 Spring Boot 프로젝트 구조를 분석해. 그리고 AI 엔진에서 쏘는 JSON(`speed`, `plateNumber`)을 받을 수 있는 REST API 엔드포인트를 만들고, DB에 저장하는 로직까지 전부 구현해 줘."

## 💡 2. 터미널 권한의 극대화: "스스로 실행하고 고쳐라"
클로드 코드의 가장 무서운 점은 에러를 두려워하지 않는다는 것입니다. **서버 실행과 디버깅 루프**를 통째로 위임하십시오.

* **마법의 프롬프트:**
  > "지금 작성한 코드를 `./gradlew bootRun` (또는 `uvicorn main:app`)으로 실행해 봐. 
  > 만약 에러 로그가 발생하면, 나한테 물어보지 말고 네가 원인을 분석해서 코드를 수정한 뒤에 정상적으로 서버가 뜰 때까지 반복해서 다시 실행해."
* **효과:** 리더님이 커피 한 잔 마시고 오면, 클로드가 5번의 에러를 스스로 맞고 코드를 다 고쳐서 서버를 띄워놓습니다.

## 💡 3. 도메인(컨텍스트)의 분리: `/clear` 의 마법
현재 리더님은 3대의 PC(AI, Spring, Vue.js)를 다루는 풀스택 환경입니다. 클로드는 대화가 길어지면 이전 코드를 기억하려다 환각(Hallucination)에 빠집니다.

* **규칙:** 백엔드(Spring) 작업을 하다가 프론트엔드(Vue.js) 작업으로 넘어갈 때는 **반드시 터미널에 `/clear`를 입력**하여 클로드의 뇌를 초기화하십시오. 
* **효과:** 불필요한 메모리(토큰) 낭비를 막고, 각 도메인에 맞는 가장 날카로운 코드를 뽑아냅니다.

## 💡 4. 파일 읽기/쓰기 권한 제어 (보안 및 속도)
클로드가 프로젝트 전체를 훑게 내버려 두면 토큰 비용이 급증하고 속도가 느려집니다. 범위를 좁혀주는 것이 핵심입니다.

* **특정 파일만 지정:** "오직 `services/speed_detector.py` 파일만 분석해서 호모그래피 로직을 최적화해."
* **글로벌 승인 (위험하지만 빠른 방식):** 터미널을 열 때 `claude --dangerously-skip-permissions` 플래그를 주면, 파일을 수정할 때마다 리더님께 (y/n)을 묻지 않고 빛의 속도로 코드를 덮어씁니다. (단, Git Commit이 되어 있는 안전한 상태에서만 쓰십시오!)

## 💡 5. 나만의 룰 북(Rule Book) 만들기 : `CLAUDE.md`
이것이 바이브 코딩의 '끝판왕' 기술입니다. 프로젝트 최상위 폴더에 `CLAUDE.md`라는 파일을 만들고, 리더님의 아키텍처 철학을 적어두십시오. 클로드가 터미널에서 켜질 때마다 이 파일을 읽고 규칙을 절대적으로 복종합니다.

**[CLAUDE.md 예시]**
- 우리는 Headless AI 아키텍처를 쓴다. 절대 화면 렌더링 코드(`cv2.imshow`)를 짜지 마라.
- AI 서버는 절대 DB에 직접 접속하지 않는다. 데이터는 무조건 Spring Boot API로 쏜다.
- 환경 변수는 무조건 `.env` 파일에서 읽어와야 한다.



# 🧠 [AI-Pass Dev] 멀티 LLM 협업 워크플로우 (Gemini/GPT x Claude Code)

**문서 상태:** 🟢 **실행 (Action Required)**
**핵심 철학:** 제미나이/GPT에게 '설계와 전략'을 맡기고, 클로드 코드에게 '타이핑과 실행'을 맡긴다.

## 1. 역할 분담 (R&R)
* **🤖 Claude Code (현장 소장):** 터미널 제어, 파일 읽기/쓰기, 서버 실행, 오타 수정, 단순 반복 코딩. (시야가 좁고, 가끔 자기가 짠 코드에 매몰되는 '터널 비전' 현상이 있음)
* **🦅 Gemini / GPT (수석 설계자):** 전체 시스템 아키텍처 설계, 복잡한 알고리즘 최적화, 보안 리뷰, 클로드의 무한 에러 루프 탈출 지원. (시야가 넓고 논리적 추론이 강함)

---

## 2. 실전 시너지 시나리오 4가지

### 💡 시나리오 1: "완벽한 작업 지시서(Prompt) 대필"
클로드 코드에게 애매하게 지시하면 엉뚱한 파일을 건드립니다. 
* **[Gemini/GPT]**에게 묻습니다: "내가 지금 Spring Boot로 과속 단속 API를 만들 건데, Claude Code 터미널에 복사해서 붙여넣을 '가장 완벽하고 구체적인 작업 지시서(프롬프트)'를 영문으로 작성해 줘. 파일 경로와 예외 처리 조건까지 다 명시해 줘."
* **[Claude Code]**에 그 프롬프트를 그대로 복붙합니다. 단 한 번의 수정 없이 완벽한 코드가 튀어나옵니다.

### 💡 시나리오 2: "무한 에러 루프(Hallucination) 강제 종료"
클로드 코드가 에러를 고치라고 시켰는데, 파일 A를 고쳤다가 파일 B가 터지고, 다시 A를 고치는 '삽질'을 무한 반복할 때가 있습니다.
* **[행동]** 클로드의 터미널 작업을 `Ctrl + C`로 중단시킵니다.
* **[Gemini/GPT]**에게 현재 코드와 에러 로그를 통째로 던지며 묻습니다: "클로드가 지금 이 에러를 못 잡고 헛발질 중이야. 근본적인 원인이 뭐야?"
* **[결과]** 제미나이가 찾아낸 '진짜 원인(예: DB 버전 충돌, 순환 참조)'을 클로드에게 알려주며 "이 방식대로 고쳐"라고 방향을 틀어줍니다.

### 💡 시나리오 3: "법전(CLAUDE.md) 편찬"
프로젝트의 규칙을 정하는 일은 철저한 논리와 아키텍처 지식이 필요합니다.
* **[Gemini/GPT]**에게 지시합니다: "우리 프로젝트는 3대의 PC로 분산된 MSA 환경이야. 이 환경에서 클로드 코드가 절대 하면 안 되는 행동과 반드시 지켜야 할 코딩 컨벤션을 `CLAUDE.md` 파일 포맷으로 작성해 줘."
* 생성된 파일을 프로젝트 루트에 저장해 두면, 클로드가 그 룰을 평생 따릅니다.

### 💡 시나리오 4: "비용(Token) 절감과 로직 최적화"
클로드 코드는 파일을 통째로 읽어 들이기 때문에 API 비용(토큰)이 꽤 빠르게 소모됩니다.
* 알고리즘 연산(예: YOLO 바운딩 박스를 활용한 호모그래피 투시 변환 공식 최적화)처럼 파일 시스템 제어가 필요 없는 순수 수학/논리 문제는 **[Gemini/GPT]** 웹 화면에서 무료로, 충분히 토론하여 함수를 완성합니다.
* 완성된 함수 코드만 클로드에게 넘겨주며 "이 함수를 `speed_detector.py`에 갈아 끼워"라고 지시하여 비용을 극단적으로 아낍니다.
